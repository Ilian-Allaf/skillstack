# Reading notes — 8 Taste Skill Lessons

Recorded on 2026-11-25 from [Eric Tech's video](https://www.youtube.com/watch?v=D5bQKp5_7Tc). Paraphrased from automatic English captions; see [provenance](SOURCE.md). "Lin" is Leon Lin, whose article the video condenses.

| Time | Notes |
|---|---|
| [00:00](https://www.youtube.com/watch?v=D5bQKp5_7Tc&t=0s) | Lin's demo prompt held nine reference images, a number to hit, and an order to keep going until it matched. He says the wording of a prompt barely matters. |
| [01:16](https://www.youtube.com/watch?v=D5bQKp5_7Tc&t=76s) | **1. References.** Lin: references carry most of the quality; an image shows light, color, material, layout and spacing that text cannot describe. Sources: a library of screens from real products, X; the presenter adds Dribbble, an MCP server of captured sites with colors and fonts extracted, naming a real app, and a browser tool that lets the agent use a site like a visitor. |
| [03:06](https://www.youtube.com/watch?v=D5bQKp5_7Tc&t=186s) | **2. Target first.** The agent needs a goal before it builds. For a web page: three different single-file HTML mockups from the references, side by side in one viewer, checked at phone width too. Ask for the same quality and mood, not a copy, so the page still looks like the product. Changes are cheap at this stage. |
| [04:10](https://www.youtube.com/watch?v=D5bQKp5_7Tc&t=250s) | **3. A number.** "Make it look good" gives no stopping point; "match the references, aim for 99.9%" says the job is not done when the page first works. Models score their own work too high, so Lin gives his own estimate ("it says 90%, I think 60 to 70%"). |
| [04:57](https://www.youtube.com/watch?v=D5bQKp5_7Tc&t=297s) | **4. Time.** The same model gives very different results in 20 minutes and in 20 hours. Lin's prompts set a minimum duration and a usage pacing rule, and end with "if you have questions, ask me now; otherwise start building". |
| [06:12](https://www.youtube.com/watch?v=D5bQKp5_7Tc&t=372s) | **5. Ban the slop.** Each prompt lists what the model must not use: beige, glowing orbs, random serif fonts, small labels above every heading, monospace uppercase text, 01 02 03 counters, shockwave rings, em dashes. A list only stops what it names and grows every time; the presenter suggests a detector with 62 checks instead. |
| [07:43](https://www.youtube.com/watch?v=D5bQKp5_7Tc&t=463s) | **6. Steps** (the presenter's, not Lin's). Design without animation first, animation after: asking for both at once degrades both. For motion, Lin gives reference videos, has the agent list every effect, transition and timing frame by frame, and take inspiration without copying any element. |
| [08:31](https://www.youtube.com/watch?v=D5bQKp5_7Tc&t=511s) | **7. Feedback.** "Make it better" does not work: name which color changes and how, or annotate a screenshot. When the problem has no name, ask the agent to describe what it built (layout, fonts, colors) to get the words. |
| [09:05](https://www.youtube.com/watch?v=D5bQKp5_7Tc&t=545s) | **8. Another judge.** Lin: the agent that built it is the worst judge of its own work. Subagents with no context rate it; the builder keeps fixing until they give 9.2/10. The judge can be another model family. |
| [10:03](https://www.youtube.com/watch?v=D5bQKp5_7Tc&t=603s) | **Cook.** "Give your agent a target, a bar, and time, then let it cook." It asks every question in one message, each with a default; writes a brief and a rounds file with scores in a folder inside the project; builds a round, sends fresh judges in their own context, fixes the weakest part, and loops until the bar. |
